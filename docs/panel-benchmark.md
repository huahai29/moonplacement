# 拼板性能实测

## 直接解析指定单元

`--panel-cell` 以前先展开整层，再按单元筛选。0.2.0 直接保留所选 SR 单元的对象，并复用原来的单元分隔和绘制顺序检查。实测沿用下方的顶铜输入与环境，比较解析到单元可核验的耗时，每组为五次独立进程的中位数。

| 实板顶铜输入 | 准备耗时 ms（整板后筛选 → 直接解析） | 峰值 MiB（前 → 后） | 结果 |
| --- | ---: | ---: | --- |
| 2×2 | 24.89 → 24.47 | 53.0 → 52.9 | 从 392 个整板对象缩到 98 个，报告 SHA-256 相同 |
| 5×5 | 30.90 → 24.36 | 59.6 → 52.7 | 从 2,450 个整板对象缩到 98 个，报告 SHA-256 相同 |
| 10×10 | 整板展开拒收 → 24.01 | 51.2（拒收）→ 53.1 | 直接保留 98 个对象，完成 12 颗器件核验 |

双面验收另外选取第 10 行第 10 列。两张坐标表中的 D1 同时偏移时，两表对比无差异，双面铜层报告能定位到 D1 的 `pad_offset`。这组输入用 KiCad 原生单板铜层构造。[实测偏位量](acceptance-results.md#kicad-实板拼板)

## 0.1.1 清除对象索引

Windows x64、Intel Core i7-14700HX、Node.js 24.18.0、`moonc 0.10.16+b1a0e846e`，使用 JS release 构建。每组启动五个独立进程，取各阶段和峰值常驻内存的中位数。计时不含读文件、进程启动和输出 JSON；核验包括两表配准、铜层核验和报告生成。内存是整个 Node.js 进程的峰值。

| 输入 | Gerber 解析 ms（前 → 后） | 选单元 ms（前 → 后） | 核验 ms（前 → 后） | 峰值 MiB（前 → 后） |
| --- | ---: | ---: | ---: | ---: |
| 实板铜层 2×2 | 24.0 → 23.7 | 0.76 → 0.86 | 2.94 → 2.87 | 52.9 → 53.0 |
| 实板铜层 5×5 | 29.9 → 29.4 | 0.77 → 0.76 | 2.79 → 3.03 | 59.5 → 59.4 |
| 实板铜层 10×10 | 21.4 → 21.4（拒收） | — | — | 51.2 → 51.1 |
| 400 焊盘、404 个清除对象 | 11.7 → 11.0 | — | 10.88 → 10.88 | 53.2 → 52.4 |
| 1,600 焊盘、1,616 个清除对象 | 19.7 → 19.8 | — | 32.91 → 21.34 | 58.0 → 59.8 |
| 4,900 焊盘、4,949 个清除对象 | 35.2 → 34.5 | — | 120.59 → 39.86 | 74.6 → 83.8 |

实板输入来自 [KiCad 7.0.11 开源板验收](real-panel.md)，只把原生顶铜外的 SR 行列数改为 2、5 或 10。只核验第一单元的 12 颗器件。10×10 触发既有的 200,000 对象及轮廓顶点上限，解析耗时是返回错误所需时间。未放宽上限。

清除密集组为合成压力测试：多数清除对象落在焊盘之间，少数焊盘有两个候选清除对象，检验原绘制顺序能否保留。在 4,900 焊盘案例上，核验约为原耗时的三分之一，解析加核验合计约从 156 ms 降至 74 ms。六组输出的 SHA-256 均一致，包括受影响引脚、对象编号和拒收信息。另以线性扫描为对照，对 1,125 次空间查询验证相同的结果。此数据适用于固定用例；当清除范围大量重叠时，索引能排除的对象会减少。

索引仅用于寻找后绘制的清除对象：先按空间包围范围剪枝，再用原几何条件复核，继续选择绘制序号最大的候选。它不改变焊盘判定，也不加速缺少位号时的整层点查询。

## 复跑

```sh
moon build --target js
node tests/kicad-panel.mjs
moon build --target js --release
node tests/bench-panels.mjs _build/real-panel _build/panel-after.json
```

如已有优化前的同一基准报告，可在末尾加上其路径，脚本会逐案例核对完整报告的 SHA-256。CI 运行三次并保存 JSON，同时断言固定顶铜输入的直接解析只保留 98 个对象。10×10 直接解析使用 128 MiB 的峰值进程内存预算，耗时作为观测值记录。
